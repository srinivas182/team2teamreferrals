# Security and accessibility review — November 2026 (Sprint 53a)

An external-style review before launch: OWASP Top 10 (2021) checks, a dependency audit, access-control and
data-isolation tests across every role and route, and a WCAG 2.1 AA audit. Every finding below is fixed or recorded
as an accepted risk with a reason. **No high or critical findings remain open.**

## How it's checked from now on

| Check | Where | Fails the build when |
|---|---|---|
| Access control on every route (sign-in, active account, staff, permission) | `tests/Feature/Security/AccessControlTest.php` | a member or admin route is added without them |
| CSRF exemptions | same | a request that changes something skips CSRF and isn't on the reviewed list, or isn't rate limited |
| Rate limits | same | a request that changes something without signing in has no limit |
| Data isolation sweep (over 400 requests, with real data) | same | an outsider, or the owner of another network, sees or changes anything through any member route |
| Admin permissions | same | staff without a permission can open a screen that needs it |
| Regression checks (security.txt, password guessing, cookies, escaping, fake images, admin two-step) | `tests/Feature/Security/HardeningTest.php` | any of these regress |
| Dependency advisories | CI quick checks: `composer audit`, `npm audit --omit=dev --audit-level=high` | a known advisory affects shipped code |
| WCAG 2.1 A/AA (axe-core) on 56 screens, light, dark and phone | `scripts/ci/visual.mjs` | any serious or critical problem |
| Keyboard journeys, visible focus, reflow at 320 px | `scripts/ci/keyboard.mjs` | any step fails |

| # | Area (OWASP) | Finding | Severity | Status |
|---|---|---|---|---|
| 1 | A01 Broken access control | The admin copies of shared screens (network applications, seat map, invitations, training-video studio, reports) relied only on checks inside the controller; the routes didn't require staff or a permission. No data was exposed (the controller checks held), but one missed check would have been enough. | Medium | Fixed: the admin routes now also require staff and `groups.manage`, `industries.manage` or `referrals.view`. |
| 2 | A01 | Member search (`/app/search`) didn't check the account was still active. | Low | Fixed. |
| 3 | A01 | Removing a team member, deleting a licence, revoking an invitation, deleting a saved view, removing time off or withdrawing a testimonial with someone else's id did nothing but still reported success. | Low | Fixed: these now answer "not found". |
| 4 | A04 Insecure design | The network owner's copies of "delete saved prospect view" and "tick off a task" crashed (500) because the id was read by position, not by name. | Low | Fixed. |
| 5 | A07 Identification and authentication | "Email me a sign-in link", "This wasn't me" and the partner sign-out had no per-IP rate limit (the sign-in link already had one per email). | Low | Fixed: per-IP limits added. |
| 6 | A05 Security misconfiguration | Session cookies weren't HTTPS-only unless an environment variable was set. | Medium | Fixed: HTTPS-only by default in production. |
| 7 | A05 | No way for outside researchers to report a problem. | Info | Fixed: `/.well-known/security.txt` (RFC 9116), with a "Security contact email" in Admin → System → General. |
| 8 | A03 Injection (uploads) | Two image uploads checked the content but not the declared type. | Info | Fixed: both now also require JPEG, PNG or WebP (content is still checked and re-encoded). |
| 9 | A06 Vulnerable components | Pending updates in Dependabot #115 (JavaScript) and #108 (PHP); #108 failed because it mixed in major upgrades. | Low | Fixed: every minor and patch update applied (Playwright held, see below); five major upgrades held back as accepted risks. Two development-only advisories (`minimatch`, `glob`) fixed by pinning patched versions. |

Checked and found sound: SQL built only from constants or bound values; no open redirects; webhook URLs blocked from
private and reserved networks (SSRF); people's own text escaped wherever the server builds HTML; secrets absent from
the repository; strict CSP with nonces, HSTS, frame denial and a restrictive Permissions-Policy; two-step sign-in
required for staff; password guessing locked after five tries a minute.

## Accessibility (WCAG 2.1 AA)

Fixed in this review:

- Small grey text (`text-subtle`) raised to 4.8:1 contrast; red and blue badge text darkened to at least 5.1:1.
- In dark mode, status text (success, warning, danger, info) uses lighter shades, and text on the blue button colour uses the dark ink colour (5.3:1 instead of 3.5:1).
- "Ask Ally" and the search buttons are named by their visible words (WCAG 2.5.3).
- A colour field without a label, and a link told apart from text by colour alone, fixed.
- Focus goes back to "Ask Ally" when its panel closes; the home page's industry box and the press video show focus.
- The home page and sign-in pages no longer scroll sideways at 320 pixels wide.

Known limits are published on the accessibility statement at `/accessibility`.
